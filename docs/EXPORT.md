# JSON export

Daymark Habits exports **`habit-widget.json`** in the vault root. This existing filename is shared with the optional Scriptable companion. There is no `habit.json` export.

The file is a read-only snapshot of the user’s **current local date**, not a full backup. Editing the file never changes habit check-ins. For full history, back up the vault configuration folder, including `.obsidian/plugins/niyoj-daymark/data.json` (or its equivalent in a custom configuration folder).

## Export

- Run **Daymark Habits: Export widget snapshot** for a one-time export, even if automatic export is off.
- Enable **Settings → Daymark Habits → Export widget snapshot after changes** for updates after changes, on startup, and after a detected local midnight while the plugin is running.
- Obsidian must be running to generate new snapshots. Turning automatic export off leaves the last file in place.

## Schema, version 1

```json
{
  "version": 1,
  "date": "2026-11-14",
  "updatedAt": "2026-11-14T08:30:00.000Z",
  "remaining": [
    {
      "id": "task-plan",
      "name": "Plan the day",
      "routine": "Morning ritual",
      "color": "#249c03"
    }
  ],
  "completed": [
    {
      "id": "task-stretch",
      "name": "Stretch for five minutes",
      "routine": "Morning ritual",
      "color": "#249c03"
    }
  ]
}
```

The example is illustrative. IDs in real exports are generated by Daymark.

The optional [Daymark Today Scriptable widget](../companion/Daymark-Today.js) reads this schema through a bookmark named **Daymark Widget**. The current export does not include `projectedStreak`; its **If done** column therefore shows **—**. The widget mockup's projected streak values are illustrative.

| Field | Meaning |
| --- | --- |
| `version` | Snapshot schema version; currently `1`. |
| `date` | Local calendar date, `YYYY-MM-DD`. |
| `updatedAt` | ISO timestamp of snapshot generation, in UTC. |
| `remaining` | Tasks scheduled for `date` without a recorded check-in. |
| `completed` | Tasks scheduled for `date` with a recorded check-in. |
| `id` | Stable task ID. |
| `name`, `routine`, `color` | Task name and routine name/color effective on that date. |

Unscheduled tasks and routines are omitted. An empty day has two empty arrays. Task counts are individual tasks, while analytics measure completed routine days; a partly completed routine can therefore have entries in both arrays. Freezes do not fabricate completed tasks.

## Ordering and errors

Exports share the same queue as data saves. A manual export requested immediately after a check-in includes that check-in once persistence succeeds. Existing files are replaced through Obsidian’s atomic `Vault.process`; new files use `Vault.create`, keeping Obsidian’s file cache current.

If export fails after a check-in has been saved, the check-in remains saved and a notice reports that widget export failed. Retry with the export command after resolving the write problem. A folder named `habit-widget.json` blocks export and produces an explicit message.

## Verification

`tests/export.test.ts` exercises both the source and production bundle: schema, local date, custom schedules, renamed tasks/routines, colors, empty exports, repeated replacement, pending saves, automatic export, startup, local-midnight rollover, disabling export, and failure/recovery. `tests/widget-today.test.ts` checks the supplied Daymark Today script against real exports, file/folder bookmarks, iCloud download handling, compact/large row limits, outdated dates, invalid files, previews, and refresh requests. `tests/widget.test.ts` checks the earlier compact companion's current/stale/missing/malformed snapshot handling.

`scripts/export-ui-check.mjs` verifies actual `Vault.create`/`Vault.process` behavior in a separate Obsidian runtime, the settings toggle, manual command, automatic updates, pending check-ins, and write-failure recovery. It refuses to run outside `/private/tmp/daymark-runtime-vault` and restores records and export bytes afterwards.

The real Obsidian path was verified on macOS in Obsidian 1.15.1. Physical iPhone file bookmarks, iCloud access, and Home Screen refresh require device testing.
